## 1. 서비스 개요

채용 공고(또는 직무)를 입력하면 AI가 맞춤 면접 질문을 생성하고,
**텍스트 채팅**으로 모의 면접을 진행한 뒤 **정량 피드백과 성장 추적**을 제공하는 모바일 앱.

- 한 줄 정의: "공고만 넣으면 그 회사·직무에 맞춰 실전 면접을 연습하고 피드백받는 AI 면접 코치"
- 플랫폼: 모바일 앱 (iOS / Android)

---

## 2. 타겟 사용자 & 문제 정의

### 타겟
- 취업 준비생
- 이직 준비자
- 공통점: 면접에 어려움·부담을 느끼는 사람

### 해결하려는 문제
- 실전 면접 연습 기회가 부족하다
- 공고별 맞춤 대비가 어렵다 (회사·직무마다 다른데 일반적인 연습만 하게 됨)
- 내 답변이 좋은지 나쁜지 객관적으로 알기 어렵다

## 3. 핵심 기능

### 3.1 입력 (공고 + 지원자 정보)

#### (1) 공고 입력 (3가지 방식)
| 방식 | 설명 |
|------|------|
| 텍스트 붙여넣기 | 주요 업무·자격 요건·우대 사항을 직접 붙여넣기 |
| URL 자동 추출 | 채용공고 URL 입력 → 본문 자동 파싱 |
| 직무 템플릿 | 공고 없이 직무만 선택해서 일반 질문으로 진행 |

#### (2) 지원자 정보 입력 (꼬리질문 품질의 핵심)
실제 면접 질문의 상당수는 *지원자* 기반("자기소개", "왜 이직?", "본인 역할은?").
공고만으론 질문이 겉돌기 때문에 지원자 정보를 받아 맞춤 질문·꼬리질문에 활용.

| 항목 | 필수 여부 | 설명 |
|------|-----------|------|
| 경력 / 자기소개 | 권장 | 면접관이 파고들 재료 |
| 이력서 | **선택 (스킵 가능)** | 업로드 시 더 정밀, 없으면 경력·자소서로 진행 |

> 이력서는 진입 장벽이 되므로 선택 처리. 미입력 시에도 공고+자소서 기반으로 정상 진행.

### 3.2 면접 진행
- 입력된 공고 + 지원자 정보 기반으로 **맞춤 질문 자동 생성**
- **질문 구성 (공고에만 국한하지 않음)**:
  - 공고 기반 직무 질문
  - 면접에서 나올 법한 일반 질문 (자기소개, 지원동기, 인성, 장단점 등)
  - **꼬리 질문(follow-up)** — 답변에 따라 파고듦, *횟수제 카운트 제외*
- **면접 유형 선택 (사용자 선택)**: 일반 면접 / 압박 면접 / 인성 면접 / 직무(기술) 면접 / 임원 면접 등
  → 선택한 유형에 따라 질문 톤·구성이 달라짐
- **면접관 페르소나 (사용자 선택)**: 부드러운 / 냉철한 / 깐깐한 등 페르소나를 골라 톤 조절
- **꼬리질문 종료 조건**: 지원자가 해당 주제를 **충분히 이해하고 있다고 판단되면** 꼬리질문 중단하고 다음 질문으로
- **언어 지원 (사용자 선택)**: 한국어 / 영어 등 면접 진행 언어 선택 (영어 면접 대비)
- **난이도 설정**
- **질문 개수**: 사용자가 직접 설정 (예: 3 / 5 / 10개, 기본 질문 기준 / 꼬리질문 별도)
- **진행 방식**: 텍스트 채팅 (타이핑)
- **"모르겠습니다" 처리**: 사용자가 답을 모를 때 넘어가기 제공 (막히지 않게)
- **중간 저장 & 이어하기**: 면접 도중 일시정지 → 나중에 이어서 진행 가능

### 3.3 ⭐ 피드백 (핵심 기능)
- **타이밍**: 실시간 피드백(답변마다) + 최종 종합 리포트
  - **실시간 피드백 on/off 토글 제공** — 압박 면접 등 몰입이 필요할 땐 끄고, 끝난 뒤 최종 리포트로 확인
- **평가 방식**: 점수 / 등급화 (정량)
- **평가 항목**:
  1. 답변 내용의 논리 / 설득력
  2. 직무 적합성 (공고 부합 정도)
  3. 답변 구조 (STAR 등)
  4. 키워드 / 전문용어 사용
  5. 모범 답안 제시 — **일반 모범답안** 형태 (해당 질문에 대한 좋은 답변 예시 제시)

#### 최종 판정 (면접 종료 시)
- **100점 만점 점수** 부여 — **점수 표시 on/off 토글** 제공 (점수 부담 없이 연습하고 싶은 사용자 배려)
- **합격 / 불합격 판정**: AI가 공고·답변을 종합해 주관적으로 판정
  - 판정 근거(왜 합/불인지)를 함께 제시해 납득도 확보
  - 점수 토글을 꺼도 합/불 판정과 피드백은 제공 가능
- **리포트 공유 / 내보내기**: 최종 리포트를 이미지·PDF 등으로 공유·저장 (바이럴 요소)

### 3.4 기록 & 성장 추적
- **면접 대화 전문 재열람**: 지난 면접의 **질문·내 답변·꼬리질문·피드백·최종 리포트**를
  대화 형태 그대로 다시 열어볼 수 있음 (서버 저장 → 기기 교체·재설치에도 유지)
- 면접 목록에서 언제든 해당 면접을 선택해 전체 트랜스크립트 확인
- 성장 추이 시각화:
  - **메인**: 종합 점수 추이 라인 차트 (+ 난이도·면접유형 태그로 맥락 표시)
  - **보조**: 최근 면접 항목별 레이더 차트 / 항목별 추이 (약점 진단용)
  - **참여 지표**: 총 면접 횟수, 연속 연습일(스트릭) 등 (리텐션)

> 종합 점수만 보면 난이도·유형 차이로 비교가 왜곡될 수 있어 태그를 함께 표기.
> 항목별 지표로 "어느 역량이 약한지"를 진단할 수 있게 보조.

### 3.5 지원 직무 카테고리 (확장)

개발 직무에 한정하지 않고 **전 직군**을 대상으로 한다. 사용자가 공고를 안 넣어도
직무 템플릿만으로 면접 연습이 가능하도록, 대분류 → 세부 직무 구조로 제공.

| 대분류 | 세부 직무 예시 |
|--------|----------------|
| 개발 | 백엔드, 프론트엔드, 모바일(iOS/Android), 데이터 엔지니어, AI/ML, DevOps·인프라, QA, 보안 |
| 기획 | 서비스 기획, PM / PO, 전략 기획 |
| 디자인 | UX/UI, 프로덕트 디자인, BX·브랜드, 그래픽 |
| 마케팅 | 퍼포먼스 마케팅, 콘텐츠 마케팅, 브랜드 마케팅, 그로스 |
| 영업·세일즈 | B2B 영업, 기술 영업, 해외 영업 |
| 데이터·분석 | 데이터 분석가, BI, 데이터 사이언티스트 |
| 경영지원 | 인사(HR), 재무·회계, 법무, 총무 |
| 고객지원 | CS, CX |
| 기타 전문 | 의료, 교육, 연구, 금융 등 |

> **직무별 평가 가중치 차별화 (중요)**
> 같은 평가 항목이라도 직무에 따라 무게가 달라야 한다.
> - 개발: 기술 깊이 · 문제 해결 과정 비중 ↑
> - 영업·마케팅: 설득력 · 커뮤니케이션 · 성과 수치 비중 ↑
> - 디자인: 의사결정 근거 · 포트폴리오 설명 비중 ↑
> - 기획: 논리 구조 · 우선순위 판단 비중 ↑
>
> → 직무별 평가 루브릭(가중치 프리셋)을 별도 설계 필요.

### 3.6 공고 수집 방식 (기술 검토)

'URL 자동 추출'의 현실적 실현 방안. 단계적 접근 권장.

| 방식 | 가능 여부 / 조건 | 비고 |
|------|------------------|------|
| 공공데이터 API (워크넷) | 즉시 가능 (무료·자동승인) | 회사명·자격요건·우대조건·급여 등 풍부. 단 공공·중소 위주, 사기업/IT 공고 약함 |
| 원티드 OpenAPI | 인증키 신청 (3영업일) | 채용·회사정보 연동 가능. B2B 성격 |
| 사람인 / 잡코리아 API | 신청·심사 필요 | 잡코리아는 공공기관·학교 대상, 개인 서비스는 거절 가능성 높음 |
| URL → JobPosting 파싱 | 즉시 가능 | 페이지의 schema.org JobPosting(JSON-LD) 추출. 크롤링보다 안정적 |
| 무단 크롤링 | ❌ 지양 | 원티드 등 약관상 명시적 금지, 법적 리스크 |

> **단계적 로드맵**
> - 1차(MVP): **텍스트 붙여넣기가 기본.** URL의 JobPosting 구조화 데이터 파싱은 되면 추가(best-effort), 실패 시 자동으로 복붙 입력으로 폴백
> - 2차: 공공데이터 API 연동 (무료·자동승인)
> - 3차: 원티드 등 민간 API 제휴 (서비스 신뢰도 확보 후)
>
> ※ URL 자동 추출은 사이트마다 성공률이 다르므로 **필수 기능으로 두지 않는다.** 복붙만으로도 완결되게 설계.

### 3.7 계정 / 로그인 (소셜 로그인 필수)

- **소셜 로그인 필수**: 비로그인 체험 없음. 진입 즉시 로그인해야 서비스 이용 가능.
- **이유**: 면접 이력·성장 추이가 계정에 묶여야 핵심 가치가 유지됨 + 횟수제(하루 20개) 어뷰징 방지 + 결제·푸시 연동.
- **로그인 수단**:
  - 카카오 (한국 타겟 사실상 필수)
  - 애플 (Sign in with Apple)
  - 구글 (선택)

> ⚠️ iOS 심사 제약 (App Store 지침 4.8)
> 카카오·구글 등 소셜 로그인을 쓰면, 동등한 프라이버시 보장 로그인 수단을
> 함께 제공해야 한다 (이름·이메일만 수집 / 이메일 비공개 가능 / 무동의 광고수집 없음).
> → Sign in with Apple이 이 요건을 충족하므로 **애플 로그인 동반 탑재 필수.**

#### 닉네임 / 프로필 처리 (중요)
소셜 로그인은 이름·닉네임을 항상 주지 않으므로, **온보딩에서 닉네임을 직접 입력받는다.**

- **애플**: 이름·이메일을 **최초 인증 1회에만** 제공. 재로그인 시 미제공 + 이름 건너뛰기 가능 + 이메일 Private Relay 가능.
  → 첫 로그인 시 받은 값을 즉시 DB 저장 필수 (안 하면 영구히 재취득 불가).
- **카카오**: 닉네임·프로필은 동의항목 (거부 시 null), 실명·이메일은 비즈앱 + 추가 동의 필요.
- **구글**: 이름·이메일 비교적 안정적으로 제공.

> 처리 원칙
> - 소셜 응답값은 **기본값(prefill)** 으로만 사용, 없으면 빈칸
> - 앱 내 표시 닉네임의 정본(source of truth)은 **온보딩 입력값**
> - 이메일은 nullable로 설계 (애플 relay/거부 대비)

### 3.8 콘텐츠 가드레일 (불법·차별 질문 방지)

AI가 생성하는 질문·피드백이 부적절하지 않도록 가드레일 적용.

- **생성 금지**: 나이·결혼·임신·출산·가족관계·종교·출신지역·외모 등
  한국 채용 맥락에서 **불법·차별 소지가 있는 질문**은 AI가 생성하지 않도록 프롬프트·필터링.
- **코칭으로 전환**: 사용자가 실제 면접에서 이런 질문을 받았을 때의 대응법을
  별도 코칭 콘텐츠로 제공 (역이용 가능 — 차별화 포인트).
- 부적절한 사용자 입력·욕설 등에 대한 기본 모더레이션도 고려.

## 5. 플랫폼 / 기술 방향

- 모바일 앱 (iOS / Android)
- **프레임워크: Flutter (확정)**
  - 근거: 텍스트 채팅 중심이라 크로스플랫폼으로 충분 / 국내 앱 전담 포지션 1위 스택 / 기존 iOS 네이티브·Fastlane·CI 자산이 그대로 강점 / Dart 진입 낮음
  - 상태관리·아키텍처: Riverpod(또는 Bloc) + Clean Architecture + get_it(DI) 방향
  - ※ RN(React Native)은 웹을 *메인 전략*으로 갈 경우에만 재검토 (React 웹과 로직 공유 이점). 현재 기준(모바일 우선 + 이직 카드 겸용)에서는 Flutter 우위
- **네이티브 모듈 전략 (플랫폼 채널)** — 포트폴리오 가치 겸용
  - 홈 위젯: 오늘 남은 무료 질문 수 / 연속 연습일(스트릭)
  - Live Activity: 면접 세션 진행 상태(예: 질문 2/5) 잠금화면 표시
  - 로컬 푸시: 매일 면접 리마인더
  - → 최소 하나는 플랫폼 채널로 직접 구현해 "Flutter + 네이티브 브릿지 + 출시" 확보
- **서버: NestJS / TypeScript (확정)** — 기존 자산(service-monitor 등) 재활용
  - **PostgreSQL**: 면접 세션·질문·답변·평가 등 관계형 데이터
  - **Redis**: 하루 질문 카운터(자정 TTL 리셋), 세션 캐시, LLM 응답 캐시
  - **LLM 프록시**: API 키는 앱에 두지 않고 **서버가 프록시** — 프롬프트 구성·LLM 호출·SSE 스트리밍 중계·가드레일·비용 통제를 서버 한 곳에서
  - 스케줄러(cron)로 자정 리셋 등 배치 처리
  - 배포: Docker + EC2 (기존 인프라 경험 활용)
- AI: 질문 생성 / 꼬리질문 / 피드백 모두 LLM 기반 (모델·프롬프트 설계 추후)

> 대안: LLM 파이프라인이 크게 복잡해지면(멀티스텝 에이전트·벡터검색 등) Python(FastAPI) 재검토.
> 현재 요구(프롬프트→응답→평가) 수준에선 NestJS로 충분.

## 6. 개인정보 / 보안

이력서·자기소개·면접 답변은 **민감 개인정보**이며, 이를 LLM(외부 API일 경우 외부)으로
전송하는 구조이므로 개인정보보호법 준수가 필수.

### 수집 항목
| 항목 | 민감도 | 비고 |
|------|--------|------|
| 소셜 계정 정보 (닉네임/이메일) | 중 | 이메일 nullable |
| 이력서 / 경력 / 자기소개 | **높음** | 선택 입력, LLM 분석 대상 |
| 면접 질문·답변·평가 기록 | 중 | 성장 추이용 저장 |

### 처리 원칙
- **수집·이용 동의**: 회원가입/입력 단계에서 항목별 동의 (필수/선택 구분)
- **LLM 전송 고지**: 입력 데이터가 AI 분석을 위해 LLM에 전송됨을 명시 고지·동의
  (외부 LLM API 사용 시 **처리위탁/국외이전** 고지 필요)
- **보관·파기**: 면접 기록 보관 기간 명시, **회원 탈퇴 시 지체 없이 파기**
- **최소 수집**: 이력서 원문은 분석 후 미저장 옵션 검토 (민감도 최소화)
- 처리방침·이용약관 문서 별도 작성, 앱 내 접근 가능하게

> ISMS-P 관점: 데이터 흐름(수집→LLM 전송→저장→파기)별 보호조치 정리 필요.

## 7. 예외 · 엣지 처리

기획 레벨에서 방향만 정의. 세부는 기능 명세 단계에서 구체화.

| 상황 | 처리 방향 |
|------|-----------|
| URL 파싱 실패 | "자동 추출 실패" 안내 → 텍스트 직접 입력으로 폴백 |
| LLM 응답 지연·오류 | 로딩/재시도 UI, 일정 시간 초과 시 에러 안내 + 재시도 |
| 네트워크 끊김 | 중간 저장(이어하기)으로 복구, 작성 중 답변 임시 보관 |
| 빈 / 성의 없는 답변 | 재답변 유도 또는 낮은 점수 + 개선 안내 |
| 평가에 납득 못 함 | 재평가 요청 / 피드백(👎) 흐름 제공 |
| 평가 점수 일관성 | LLM 비결정성 대비 — temperature·시드 고정, 루브릭 명시로 편차 최소화 |
| 직무 템플릿 콜드스타트 | 인기 직무 기본 질문 세트 사전 준비 vs 즉석 생성 (택1) |

## 8. 추가 논의 필요 (미정 항목)

아래는 1차 기획에서 방향만 잡고 세부는 후속으로 미룬 부분.

- [ ] **구독 가격·등급 구성**: 구독 티어 가격대, 무료 대비 혜택 상세 (구독제 방향은 확정)
- [ ] **URL 자동 추출 범위**: 지원 채용 사이트 (best-effort, 필수 아님으로 확정)
- [ ] **면접관 페르소나 세트**: 구체 페르소나 종류·톤 정의
- [ ] **모범 답안 톤/분량**: 일반 모범답안의 상세 포맷
- [ ] **리포트 공유 포맷**: 이미지 카드 / PDF 등 구체 형태

### 해결된 항목 (참고)
- ✅ 입력: 공고(복붙 기본, URL은 best-effort) + 지원자 정보(이력서 선택)
- ✅ 질문 범위: 공고 기반 + 일반 면접 질문 + 꼬리질문
- ✅ 면접 유형: 일반/압박/인성/직무/임원 등 사용자 선택
- ✅ 면접관 페르소나 / 진행 언어: 사용자 선택
- ✅ 꼬리질문 종료: 이해도 충분 판단 시 중단
- ✅ 횟수제 단위: 기본 질문 20개, 꼬리질문 미카운트, **자정 리셋**
- ✅ 최종 판정: 100점(표시 토글) + 합/불 판정(근거 제시)
- ✅ 실시간 피드백 on/off 토글, "모르겠습니다" 넘어가기
- ✅ 모범 답안: 일반 모범답안
- ✅ 성장 추이: 종합 점수(메인) + 항목별(보조) + 참여 지표
- ✅ 수익 모델: **구독제(Freemium)**
- ✅ 데이터 저장: **서버 저장**
- ✅ 리포트 공유/내보내기 지원
- ✅ 불법·차별 질문 가드레일
- ✅ 로그인: 소셜 로그인 필수 (카카오·애플·구글)

## 9. 다음 단계 (개발 진행 순서)

단계별로 끊어 진행. 각 단계 산출물이 다음 단계의 입력이 된다.

1. **기획서** (본 문서) — 모든 단계의 기준
2. **기능 명세 / 유저 스토리** — 화면별 기능·예외 케이스로 분해
3. **화면 정의서** — 와이어프레임 기반, 화면별 구성요소·상태(로딩/에러/빈 상태)
4. **데이터 모델 / ERD** — users / 면접 세션 / 질문 / 답변 / 평가
5. **API 명세 (REST)** — NestJS 엔드포인트 + 요청·응답 스키마 (4번 전제)
6. **AI 프롬프트 설계** — 질문 생성 / 꼬리질문 / 평가 루브릭(직무별 가중치) + 출력 JSON 스키마 고정 ⭐ 품질 핵심
7. **기술 아키텍처** — Flutter 앱 구조 + 서버 + LLM 연동 + 소셜 인증 + 인프라
8. **MVP 범위 확정** — 1차 출시 컷 (구현 착수 전 필수)
9. **구현** — 백엔드(스키마→API→LLM) → Flutter(화면→API연동→상태관리)
10. **QA + 배포** — Fastlane / GitLab CI

> 진행 팁
> - 단계마다 별도 요청으로 끊고, 기획서·ERD·API명세를 컨텍스트로 물릴 것 (예: CLAUDE.md)
> - 6번은 "알아서"로 넘기지 말고 평가 항목·가중치·출력 포맷을 직접 명시
> - 8번 MVP 컷을 9번 구현 전에 반드시 확정
