# decisions — 결정 기록 (ADR)

**왜 그렇게 정했는가**를 남기는 곳. 코드와 스펙 문서에는 결과만 남고 근거는 사라지기 때문이다.
예를 들어 코드에는 `claude-opus-5` 문자열만 남지만, 왜 Sonnet이 아니라 Opus인지는 어디에도 없다.

## 스펙 문서와 무엇이 다른가

| | `docs/*.md` (스펙) | `docs/decisions/*.md` (결정 기록) |
|---|---|---|
| 답하는 질문 | **무엇을** 만드는가 | **왜** 그렇게 정했나 |
| 시간 | 항상 현재 상태로 갱신 | **그 시점의 스냅샷 — 나중에 고치지 않는다** |
| 뒤집혔을 때 | 문서를 수정 | 새 ADR을 쓰고 옛 것을 `대체됨`으로 표시 |
| 예시 | ERD, API 명세, 화면정의서 | "왜 Opus 5인가", "왜 GitHub Flow인가" |

## 이슈로 둘까, ADR로 쓸까

> **6개월 뒤에 "왜 이렇게 됐지?"를 다시 물을 것 같으면 ADR, 한 번 읽고 닫을 거면 이슈.**

- 이슈로 충분: "닉네임 중복 방지 구현" — 코드를 보면 무엇을 했는지 알 수 있다
- ADR로 승격: "Phase A 모델을 Opus 5로 정함" — 코드에는 모델 문자열만 남고 근거가 사라진다

## 작성 규칙

- 파일명: `NNNN-영문-슬러그.md` (4자리 일련번호, 재사용하지 않는다)
- 머리말에 **상태**와 **날짜**를 적는다 — 상태는 `제안` / `채택` / `대체됨` / `폐기`
- 본문은 **배경 → 결정 → 근거 → 따라오는 결과** 순서
- **짧게.** 한 화면을 넘기면 대개 스펙 문서로 갈 내용이 섞인 것이다
- 결정이 뒤집히면 **기존 파일을 고치지 말고** 새 ADR을 쓴 뒤, 옛 파일 머리말을 `대체됨 (→ NNNN)`으로 바꾼다
