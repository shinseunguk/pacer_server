# 0004. Phase A LLM 모델은 Claude Opus 5

- **상태**: 채택
- **날짜**: 2026-08-18
- **관련**: `../Pacer_LLM비용추정_v1.md`, [0001](./0001-two-phase-launch.md), [0003](./0003-stub-interview-engine.md)

## 배경

마일스톤 2에서 `StubInterviewEngine`을 실제 LLM 어댑터로 교체하면서 모델을 정해야 했다.
후보는 Claude Opus 5 / Sonnet 5 / Haiku 4.5이고, 면접 1회당 비용이 **$0.33 / $0.20 / $0.066**으로 5배 차이가 난다.

## 결정

**세 호출 모두 `claude-opus-5`.** 비용은 모델 강등이 아니라 `effort`로 조절한다.

| 메서드 | `effort` |
|--------|----------|
| `generateQuestions` | `high` |
| `decideNextTurn` | **`low`** |
| `evaluate` | `high` (필요시 `xhigh`) |

## 근거

- **Phase A의 목적이 비용 최적화가 아니라 품질 검증이다** ([0001](./0001-two-phase-launch.md)).
  최고 티어에서 기준선을 잡아야, 나중에 모델을 내렸을 때 품질 저하의 원인이 **모델인지 프롬프트인지 구분**할 수 있다. 반대 순서로는 원인을 짚지 못한다
- 최고 티어에서도 평가가 납득되지 않으면 그건 **프롬프트·루브릭 설계 문제라는 신호**이고, 그 자체가 Phase A가 얻어야 할 정보다
- 베타 규모(월 400 면접)에서 **월 $132**는 핵심 가설 검증 비용으로 저렴하다
- `decideNextTurn`은 호출의 83%를 차지하지만 "파고들까/넘어갈까" 이진 판단이다.
  **모델을 내리기 전에 `effort: low`를 먼저 쓴다** — 모델이 같으면 톤·판단 기준이 일관되고 되돌리기 쉽다

## 대안과 기각 사유

| 대안 | 기각 사유 |
|------|-----------|
| 전량 Sonnet 5 | 월 $79로 싸지만, 품질 기준선 없이 시작하면 평가가 이상할 때 원인 규명이 불가능하다. **Phase A 후반 A/B 1순위 후보로 남긴다** |
| 전량 Haiku 4.5 | 월 $26. `evaluate`의 일관성이 서비스의 존재 이유라 여기서 타협하면 검증할 것이 없어진다 |
| 혼합(꼬리질문만 Haiku) | 31% 절감되지만 `effort: low`를 먼저 시도하지 않고 모델부터 나누는 건 순서가 틀렸다 |

## 따라오는 결과

- **강등 판정 지표는 리포트 만족도(👍 비율)** — 수집 API는 이미 있다 (#15)
- `evaluate`는 강등하지 않는다
- **Phase B 진입 전 유닛 이코노믹스 조정이 필수다.** 하루 한도 20을 매일 소진하는 사용자는
  Opus 5 기준 월 $39.5로 통상 구독가를 초과한다 (`../Pacer_LLM비용추정_v1.md` §6)
- 모델·`effort`를 바꾸면 비용 문서를 재측정한다 (같은 문서 §8)
