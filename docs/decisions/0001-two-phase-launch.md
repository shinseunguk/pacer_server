# 0001. 출시를 베타 → 정식 2단계로 나눈다

- **상태**: 채택
- **날짜**: 2026-08-14
- **관련**: `../Pacer_MVP범위_v1.md` §7

## 배경

MVP를 한 번에 내보낼지, 나눠서 낼지 정해야 했다.
한 번에 내보내려면 결제(IAP)까지 포함해야 하는데, 애플·구글 상품 등록 + 서버 영수증 검증 + 복원은
공수가 크고 면접 품질과는 아무 관련이 없다.

## 결정

**Phase A(클로즈드 베타, 결제 제외) → Phase B(정식, 수익화 부착)** 2단계로 나눈다.

- Phase A: 소셜 로그인 · 면접 준비 · 진행 · 리포트 · 히스토리. **한도 카운트 로직은 넣되 페이월은 미노출**
- Phase B: 무료 한도 활성화 + 페이월 + 구독 결제(IAP)

## 근거

이 서비스의 핵심 가설은 **"공고·직무를 넣으면 쓸 만한 맞춤 면접 + 납득되는 평가가 나온다"** 이다.
가설이 틀렸다면 결제를 붙여도 전환이 나오지 않는다. **검증되지 않은 것에 IAP 공수를 먼저 쓰는 건 순서가 틀렸다.**

- 품질 검증 → 수익화 순서라야 실패했을 때 버리는 공수가 적다
- IAP를 Phase B로 미루면 Phase A 출시 속도가 확보된다
- 한도 카운트 로직만 미리 넣어두면 Phase B에서 페이월만 켜면 된다 (구조 변경 없음)

## 따라오는 결과

- Phase A 기간에는 **결제·페이월 관련 코드를 작성하지 않는다.** 양쪽 `CLAUDE.md`에 가드레일로 명시
- `FREE_DAILY_QUESTION_LIMIT`는 Phase A에서 넉넉히 두고 Phase B에서 20으로 조인다
- Phase A → B 전환 판정 지표는 **리포트 만족도(👍 비율)**
