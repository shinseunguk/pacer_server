# 0006. 도입 질문(자기소개·지원동기)을 문항 수·평가에서 제외한다

- **상태**: 채택
- **날짜**: 2026-08-19
- **관련**: `../Pacer_AI프롬프트설계_v1.md` §3, `../Pacer_API명세_v1.md`, `../Pacer_데이터모델_ERD_v1.md`

## 배경

`questionCount`에 자기소개·지원동기가 포함돼 있었다. 프롬프트 설계 §3이
*"공고 기반 직무 질문과 일반 면접 질문(자기소개·지원동기·인성 등)을 적절히 섞는다"* 로 규정했고,
출력 스키마 예시의 첫 질문도 `"자기소개 부탁드립니다."` 였다.

그 결과 **5문항 프리셋에서 직무 질문이 3개만** 남는다. 하필 그 프리셋이
**무료 사용자가 쓸 수 있는 유일한 것**이라 체감 가치가 낮고 전환에 직결된다.

## 결정

`questionCount`의 정의를 **"평가받는 직무 질문의 수"**로 바꾼다.

| | 도입 질문 | 직무 질문 |
|---|---|---|
| 개수 | 2개 고정 | `questionCount` (5~15) |
| 문항 수 카운트 | ❌ | ✅ |
| 꼬리질문 | ❌ | ✅ |
| 평가 대상 | ❌ | ✅ |
| 대화록 | ✅ 남긴다 | ✅ |
| `progress` | 미포함 | 1..N |

## 근거

- **자기소개는 변별력이 낮다.** 준비된 스크립트를 읊는 것이라 평가 정보가 거의 없는데
  항목별 점수에는 반영되어 평가를 왜곡한다
- 카운트에서 뺐으면 **평가·진행도에서도 빼야 일관**된다
- 워밍업이므로 **꼬리질문을 붙일 이유가 없고**, `decideNextTurn` 호출도 그만큼 아낀다
- 대화록에는 남긴다 — 지원자 배경 파악에 쓰이는 컨텍스트다

## 대안과 기각 사유

| 대안 | 기각 사유 |
|------|-----------|
| 현행 유지 | 무료 체험의 체감 가치가 낮아져 전환에 직결된다 |
| 도입 질문을 프리셋별로 다르게 (짧은 건 생략) | 규칙이 늘어 설명이 복잡해진다. 카운트에서 빼면 짧은 프리셋도 직무 질문이 온전히 확보된다 |
| "도입 질문 포함" 토글 추가 | 설정이 늘어 프리셋을 만든 취지에 반한다 |
| 카운트에서 빼되 항상 앞에 붙이고 평가는 유지 | 채점 대상인데 카운트에 없는 게 더 혼란스럽다 |

## 따라오는 결과

- `MessageType`에 `intro_question` 추가 — DB 컬럼이라 **마이그레이션 필요**
- `progress`는 도입 구간에서 `current: 0`, 첫 직무 질문부터 1
- 앱은 도입 구간에 진행바 대신 워밍업 라벨을 띄운다
- 원가 **면접당 +$0.016** (질문 2개 생성 + 대화록 증가). 꼬리질문을 안 붙여 호출 수는 그대로다
- UI는 기본 질문 수를 노출하지 않고 **"약 20분 · 질문 12개 내외"**로 표기한다
  (도입 2 + 직무 5 + 꼬리 ~5 = 12)
